### Binding design (decided, not yet written)

- Class `PptxDown` (constructor and `openAsync` take `{ hiddenSlides?: boolean }`), free functions `pptxMetadata`,
  `pptxText`, `pptxTextPerPage`, `pptxStructuredText`, `pptxSlides`, `pptxMarkdown`, `pptxTables`, `pptxImages`,
  `pptxAnnotations`, `pptxNotes`, `pptxCharts`, `pptxMedia`, `pptxLayout`, `pptxInvoice`, `pptxDocument`, each
  with an `Async` twin.
- Follow the `develop-napi-rust` skill here: **do the Rust work in `compute` and convert to JS types in
  `resolve`**. docxdown-node converts in `compute` (it works, since `Buffer` is `Send` in napi 3, but it is not
  the preferred shape). A macro can declare the two task structs per reader; **write the free functions out by
  hand**, because doc comments passed through `macro_rules!` reach `index.d.ts` with a stray `r"` prefix.
- `Shape` is a union keyed on `type` with `#[napi(discriminant_case = "camelCase")]`. Both facts are verified in
  docxdown-node: napi accepts a union that contains itself, and object types used inside a union must be
  `#[napi(object)]` without `object_from_js = false`.
- `tables()` keyed like docxdown's: `rows["2"]["B"]`, with `ColumnKey` ordering and
  `#[napi(ts_type = "Record<string, Record<string, …>>")]`.
- `paperSize` union: copy the `paper_sizes!` macro from `crates/docxdown-node/src/types.rs`.
- `dest` on an annotation is a string for parity with the other packages (a slide number as text, or a jump).

## What was learned about the formats (keep)

- **docx pages.** Word marks a page with `w:lastRenderedPageBreak` in the first run of the page. A table row
  carried over a page is marked twice (where it broke, and again on what starts next); the reader counts one.
  A page that starts with an empty paragraph has no run to hold the marker, so the counted pages can fall one
  short of `docProps/app.xml`. Verified by rendering with LibreOffice in the scratch folder.
- **docx list numbers** are counted per abstract definition, not per instance; an instance with a
  `startOverride` restarts once.
- **pptx.** Slide order is `p:sldIdLst` through relationships. Many placeholders state no box of their own.
  A table's merged-away cells are present and marked `hMerge`/`vMerge`. A chart frame names a chart part; a
  SmartArt frame names a data part, which names a drawing part through `dsp:dataModelExt relId` (a relationship
  of the **slide**). A notes page always exists in PowerPoint decks and usually holds only the slide number.
- **The `pptx` crate (0.1.0)** refused 4 of 14 sample decks (relationship ids not of the form `rId7`, a zip with
  a directory entry) and cannot reach table text from a parsed slide. `ppt-rs` (`pptcli md2ppt`) works as a
  scratch-only fixture writer; it is never a dependency.
