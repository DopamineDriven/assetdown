## Workspace conventions that bind the work

- **One unit at a time.** Write it complete and tested, list deviations, report, stop. Wait for an explicit go before the next.
- **Manifests and napi configuration are Andrew's.** Propose manifest changes in chat. I write library source, binding exports and tests when asked. No new third-party dependency without his say.
- **Library crates carry no napi.** Each npm package is a thin `<name>-node` crate. JS API is a class holding the parsed document, sync methods with `...Async` twins (`AsyncTask`), parsed state behind `Arc`.
- **No new fixtures unless Andrew adds them.** Cover gaps with data built in the test (see `xlsxdown/src/testing.rs`, `pdfdown/src/images/composite/tests.rs`). Private fixtures live under `__test__/fixtures/private` (git-ignored): assertions about them go only in the ignored spec beside them, and nothing about them goes in tracked files, plans or these notes.
- **TypeScript** (`CLAUDE.md` at the root): no `any`, no `enum`, `satisfies` over `as`, no `.filter(Boolean)`, `Array.of<T>()` for typed empties, inferred return types, `.ts` import extensions, no barrels, no token caps on model calls. Tests: `node:test` on the `WorkupService` class in each `__test__/workup.ts`, never ported from old suites. American spelling everywhere.
- **Rust:** 2-space indent, `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` clean, enums with payloads on variants, `Option`/`Result` over panics, checked conversions over bare `as`.
- **Dates** are emitted as the format records them; never assume UTC.
- **Zero-config defaults** for the published packages.
- **Releases** are Andrew's: `./version.sh <package> <version>`, then a commit whose subject is exactly `<package>@<version>`; CI publishes from that.
- **Generated typings** (`index.d.ts`, `*.wasi.d.cts`) are regenerated by `yarn build` / `yarn build:wasm` and tracked. Check the diff is only the intended additions.
